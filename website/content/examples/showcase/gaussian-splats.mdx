The Gaussian Splats showcase renders a deterministic, colorful scene with the experimental
[`@luma.gl/splats`](/docs/api-reference/splats) renderer. Each source batch remains independently
owned, so additional splats can appear progressively without concatenating or reuploading the
previously prepared GPU data.

WebGPU uses storage-backed, camera-aware Gaussian rendering. WebGL2 provides an attribute-backed
fallback using the same public renderer and prepared-data interfaces. The example keeps file
format parsing separate: loaders.gl owns `.ply`, `.splat`, `.ksplat`, and related loaders, while
[`@luma.gl/arrow`](/docs/api-reference/arrow) converts Gaussian Apache Arrow batches into the
framework-independent GPU representation.

Spherical-harmonic DC colors remain unclamped floating-point radiance from loading through GPU
rendering. Standard displays use configurable exposure and tone mapping, while compatible WebGPU
displays can present directly to an extended-range `rgba16float` canvas.

The standalone example also supports an optional neighboring loaders.gl 5 alpha checkout. Start
it with `VITE_LOADERS_GL_ROOT=/path/to/loaders.gl` and open `?loaders=local` to stream the complete
741,883-splat Train scene from the same Hugging Face catalog used by loaders.gl. The source picker
also includes Dr Johnson, Playroom, and Truck; Train falls back to two GitHub-hosted segments when
the Hugging Face CDN is unavailable. Use `?loaders=local&scene=fixture` for the small parser test
asset or provide a custom `source` URL to load another supported Gaussian format.

Known GraphDECO captures use scene-specific camera-up conventions instead of assuming every scene
is Z-up; Truck also starts from its published camera position. Foreground-based framing keeps the
subject visible, manual orbit and zoom persist while additional batches stream in, and stationary
scenes avoid unnecessary redraws.
